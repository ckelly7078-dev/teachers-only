# FM-17J: bounded mathematical method and proof certificates

This additive adapter extends the private AS1 marking engine. It does not modify the active question bank, original rubrics, official source routes, scope eligibility, difficulty tiers, review service or portal. The private register is hash-, revision- and fingerprint-bound. No raw learner expression is evaluated. Observations must be faithfully transcribed from actual working by a trusted interpreter or teacher; do not populate them from reference values or infer them from a final answer. Unsupported methods remain uncertain, even when mathematically valid.

## Contract

Use `Engine.from_bundle(root)` and `ReasoningMarking.from_bundle(engine, root)` with `further_maths` on the import path. Existing FM-17D-I direct `check_work` inputs and outputs are unchanged. On new profiles, `capability` adds `reasoning_criteria`, `accuracy_criteria`, merged `checked_criteria`, and bounded coverage. `reasoning_criteria` includes any explicitly supported grouped accuracy criterion in the new envelope. Neither capability nor the proposal exposes reference answers. To combine the old and new routes, call `check_work(item_id, mode=mode, item_fingerprint=fp, work={'accuracy': {...}, 'reasoning': {...}})` with exactly the criterion keys returned for the two sets, using null for missing or unsupported observations. For a method-only profile the accuracy object is empty. Other items use their existing observation format. Gates are inherited. No model calls, persistence, automatic award, teacher approval, grades or release.

## Evidence formats and mathematics

The private register identifies the expected evidence shape for each criterion. An alternatives certificate takes `{'method': name, 'evidence': observation}`; the method identifies the actual written operation, not a self-attestation of correctness. Named observations include exact signed coefficient ratios or monic Vieta substitution, common-unit angle operations, directed displacement operands, ordered cross-product terms or determinant expansion, and selected algebraic identities, matrix and geometry substitutions. Different supported approaches have separate evidence shapes. An unrecognised approach is represented by null or `{'method':'other','evidence':null}` for an alternatives certificate. For rational values use bounded rational strings; use the inherited exact radical and structured value conventions where applicable.

`row_combination` checks actual multipliers, the exact resulting augmented equation and proportional equivalence to the required elimination. `row_dependency` checks a nontrivial dependence, residual constant and the observed logical conclusion. `row_addition` checks the chosen distinct zero-based destination/source rows, nonzero scale, and actual transformed matrix. `affine_line_proof` checks a nonzero direction, an actual base point, both exact substitutions (constant and direction coefficient), and a completeness conclusion justified by two independent equations. Arbitrary symbolic proofs, diagrams, other equivalent representations and general consequential-error marking remain outside these bounded routes.

The specific parametric complex-product challenge profile uses component equations `-b*x+a*y=h` and `x*y+c=k`. Its component observation is `[a,b,c]`, with those signs and unit coefficients fixed by the representation. Other forms must be interpreted faithfully or remain null. For the elimination criterion `{'variable': 'x'|'y', 'coefficients': [A,B,C,D]}` encodes `A*v^2+B*h*v+C*k+D=0` in the retained variable. The quadratic may be scaled by any nonzero rational. Follow-through is allowed only from the single earlier constant-product error in `c`; errors in the other observed coefficients remain outside this route. The two-mark criterion explicitly splits roots and reconstruction. Its observation has `discriminant: [coefficient_of_h_squared, coefficient_of_k, constant]` with leading coefficient one, `roots: [[coefficient_of_h, coefficient_of_sqrt_discriminant], ...]`, and `reconstruction` containing the two paired expressions for the other variable in the same branch order. Each field may be null. The two roots can be in either order, but reconstruction must match the pairing. If roots or the prerequisite quadratic cannot be established, unsupported reconstruction remains uncertain. Other grouped criteria are not split. No follow-through award is inferred from a correct answer alone. No classification or completeness marks are inferred from the factor pairs.

The new proposal may include `followthrough_criteria`, and the expressly split criterion has `subcriteria` and `possible_marks`. A status `partial` represents exactly one of its two marks established and the other not met; uncertainty remains an interval. Downstream code must not treat this as a grade or coerce unresolved marks to zero. Correct supported method evidence survives a subsequent wrong accuracy observation where the original rubric permits separate credit. Method requirements which include an intermediate result still require that result. Official CCEA M/W/MW routes remain distinct from these original M/A/R criteria; nothing is transplanted from one to the other.

## Verification boundary

Run `python -W always::ResourceWarning -m unittest discover -s further_maths -p 'test_*.py'` from the code root. Private reproduction and actual-engine audit are included in the private checkpoint only. These are mathematical and structural tests of deliberately bounded observations, not a universal proof checker, human marking validation, empirical calibration or evidence of live Studio integration. The private register and original source materials must never enter Git or a public web root.
